# همراه — نسخه بومی Android

اپلیکیشن فارسی برای ثبت آب، پیگیری مصرف دارو و قرارهای پزشکی. این پروژه مستقیماً با **Kotlin و Jetpack Compose** ساخته شده و با Android Studio باز می‌شود؛ نصب Flutter یا Dart لازم نیست. حداقل سیستم‌عامل: Android 8 (API 26).

## اجرای سریع در Android Studio

1. فایل ZIP را Extract کنید؛ پوشه پروژه را در مسیری ساده مثل `C:\Projects\hamrah-android` قرار دهید.
2. در Android Studio گزینه **Open** را بزنید و پوشه `hamrah-android` را انتخاب کنید؛ همان پوشه‌ای که `settings.gradle.kts` دارد.
3. اجازه دهید **Gradle Sync** تمام شود. بار اول برای دریافت Gradle و کتابخانه‌ها اینترنت لازم است؛ استفاده روزمره برنامه آفلاین است.
4. در Settings → Build, Execution, Deployment → Build Tools → Gradle، گزینه Gradle JDK را روی **Embedded JDK / jbr-17** یا JDK 17 بگذارید. اگر JDK همراه Studio نسخه دیگری است، JDK 17 را از فهرست Download JDK انتخاب کنید.
5. از SDK Manager، **Android SDK Platform 35** و ابزارهای پیشنهادی Studio را نصب کنید.
6. گوشی با USB debugging یا شبیه‌ساز Android 8 به بالا انتخاب کنید و دکمه سبز **Run ▶** را بزنید.

پس از بازشدن برنامه، «فعال‌کردن اعلان‌ها» را بزنید. برای یادآوری دقیق، در تنظیمات برنامه «اجازه یادآوری دقیق» را فعال کنید. در Android 12 به بالا این اجازه مستقل از اجازه اعلان است. یادآوری آب ابتدا خاموش است؛ از تنظیمات، ساعات فعال و فاصله را مشخص و آن را روشن کنید.

### ساخت APK

پس از Sync، در Terminal داخل پوشه پروژه:

Windows:
```bat
.\gradlew.bat assembleDebug
```
macOS / Linux:
```sh
./gradlew assembleDebug
```
خروجی: `app/build/outputs/apk/debug/app-debug.apk`.
این APK آزمایشی است؛ برای انتشار نسخه Release باید کلید امضای شخصی خودتان را در Android Studio تنظیم کنید.

### اگر Sync خطا داد

- از خروجی پنجره Build علت دقیق را بخوانید. خطای دانلود با تغییر کد برنامه رفع نمی‌شود؛ دسترسی اینترنت به Google Maven، Maven Central و Gradle لازم است.
- مسیر پروژه را درست انتخاب کنید؛ پوشه `app` به‌تنهایی پروژه قابل بازکردن نیست.
- SDK 35 و JDK 17 را بررسی کنید. پروژه فایل `local.properties` ندارد؛ Android Studio مسیر SDK دستگاه شما را تنظیم می‌کند.
- فایل ZIP شامل کد پروژه است، نه Android SDK یا کتابخانه‌های دانلودشده.

## ساختار داده

- `Settings`: هدف آب، ساعات فعال، فاصله، تکرار، توقف موقت، رضایت اعلان و پنهان‌کردن جزئیات.
- `Water`: شناسه، میلی‌لیتر، روز ثبت و زمان واقعی؛ مجموع روزانه از ثبت‌ها محاسبه می‌شود.
- `Medication`: برنامه مصرف، ساعت‌ها، روزها/تاریخ‌ها و فعال‌بودن.
- `Dose`: نسخه ثبت‌شده از هر نوبت، نام و توضیح همان زمان، وضعیت در انتظار/مصرف‌شده/به‌تعویق‌افتاده/مصرف‌نشده. حذف برنامه سوابق انجام‌شده را پاک نمی‌کند.
- `Appointment`: اطلاعات قرار و منطقه زمانی IANA محل قرار، همراه فاصله‌های یادآوری.
- `Reminder`: صف زمان‌بندی مشتق‌شده؛ اطلاعات صف هم رمزگذاری می‌شوند.

دارو و آب از ساعت محلی گوشی پیروی می‌کنند. قرار به منطقه زمانی محل ثبت‌شده وابسته است؛ مثلاً سفر از تهران به کشور دیگر، زمان واقعی قرار تهران را جابه‌جا نمی‌کند. تغییر ساعت و منطقه زمانی باعث بازسازی صف می‌شود. ساعت‌های ناموجود یا تکراری تغییر ساعت تابستانی طبق قواعد `java.time` حل می‌شوند: زمان ناموجود به بعد از شکاف منتقل و برای زمان تکراری اولین offset انتخاب می‌شود.

## ذخیره‌سازی و اعلان‌ها

اطلاعات در فضای خصوصی برنامه با AES-256-GCM و کلید Android Keystore ذخیره می‌شوند. نوشتن با AtomicFile انجام می‌شود؛ همه تغییرها در یک executor متوالی اجرا می‌شوند. برنامه مجوز اینترنت ندارد. نسخه فعلی پشتیبان‌گیری خودکار سیستم را غیرفعال می‌کند؛ حذف برنامه داده و کلید را از دسترس خارج می‌کند. طراحی پشتیبان‌گیری آینده در `docs/ARCHITECTURE.md` است.

AlarmManager فقط نزدیک‌ترین دسته یادآوری را نگه می‌دارد و پس از اجرا، دسته بعدی را ثبت می‌کند. دریافت‌کننده بومی بدون بازبودن Activity کار می‌کند و برای راه‌اندازی مجدد گوشی، تغییر ساعت و ارتقای برنامه صف را بازسازی می‌کند. دکمه اعلان دارو «مصرف کردم» و «۱۰ دقیقه بعد» است؛ برای آب «ثبت ۲۵۰ میلی‌لیتر» و «۱۰ دقیقه بعد». تکرار آب در صورت ثبت‌نکردن، حداکثر یک بار برای هر نوبت و داخل ساعات فعال انجام می‌شود.

Android می‌تواند اعلان‌ها را در حالت Doze، محدودیت باتری سازنده یا نبود مجوز دقیق دیرتر اجرا کند. Force stop توسط کاربر، اعلان‌ها را تا بازکردن مجدد برنامه متوقف می‌کند. روشن‌شدن گوشی نیازمند اولین بازکردن قفل است.
