# Security review

Accounts, family grants, recovery keys, pending writes, health history and reminder endpoints are sensitive. Treat browsers, other household members, backup input and the network as separate trust boundaries.

The existing Worker uses signed HttpOnly session cookies, server-side token digests, password salts and versioned peppers, per-account throttling, same-origin changes, family section/role checks, bounded inputs and redacted error diagnostics. Private care text has its own recovery mechanism. Device backups use PBKDF2-SHA-256 (600,000 iterations, 16-byte salt), AES-256-GCM with a 12-byte nonce and 128-bit tag. The 36-byte header is authenticated. The multipart server format additionally authenticates archive identity and sequence.

The portable API keeps the original password proof derivation, generates random 256-bit session tokens and stores SHA-256 digests. It checks same-origin mutation requests, bounds request size, scopes reads and writes to the current session, checks sync generation, and commits mutation and receipt atomically. Integration tests cover two owners, CAS, concurrent changes, tombstones, duplicate delivery, logout, missing origin and anonymous requests. API responses disable caching. Exceptions return a fixed public code.

Before cutover, verify registration, password reset and revocation across both systems, legacy private envelopes, delegated grants and consent, isolated remote bindings, storage retention, session expiry, distributed abuse controls, and each backup's access boundary. The legacy test suite covers several of these boundaries in its original runtime. No production security test is authorized by this run.

## Rebuild findings and verified controls

- The candidate preserves unknown legacy history container fields during ordinary writes. Device archive import rechecks its manifest digest and ordered rows before projection. PostgreSQL migration errors return aggregate failure status.
- HTTP mutations require the configured origin. Owner-bound operations require the active session and an expected-owner header. Per-account write budgets bound family, sync and backup requests. Registration/login throttling and single-use, expiring code attempts are persisted. Password reset revokes all v2 sessions. A migrated generation 1 account is ineligible for v2 authentication.
- Encrypted object keys include the owner. Reads require a ready catalog row in that account and a matching digest. The catalog transaction serializes per-account quota reservations. Client-side decryption validates structure. A cycle-local-only journal excludes cycle records and preferences from account backups. Separate encrypted cycle files stay available for explicit device export.
- Family access tests cover invitation recipients, separate households, grant direction and withdrawal. Browser tests used two isolated accounts, a real local email inbox and a password reset that invalidated the first session.
- The Node Hono adapter was upgraded after the dependency audit identified an advisory. The final production dependency audit was clean at verification time. Static responses carry a self-only script policy, anti-framing and content-type headers.
- Outstanding security gates include imported session epoch/pepper continuity, historical privacy key variants, complete delegated-policy reconciliation, reminder credentials, administrative access, hosted bindings and draining all old Worker versions. Production telemetry and the complete historical backup corpus were unavailable.

The scheduled mail adapter uses manual redirect handling and treats redirect responses as delivery failures. This works in both exercised runtimes and keeps delivery credentials on the configured provider.

The local transition test exercises scoped grant revocation, write attribution, operation receipts, owner mismatches, stale document revisions and source RPC denial while the target has accepted writes. The journal water-only control preserves other programs’ sections and rejects an implicit escalation to water write access. A source-fence setting is required on PostgreSQL rehearsal connections. An older API instance loses its write rights at the database boundary. The SQL freeze survives application restarts and rejects mutations at the database boundary.

The fixture verifies the signed legacy session against its owner, digest and expiry. A password reset revokes legacy and generation 2 sessions transactionally. Administrative revocation requires a recent authenticated session and a confirmation tag tied to the target credential. The campaign route retains the media type, range and host checks, and support history filters tickets by the signed-in account.

Administrative export GET records the audited download and streams the redacted NDJSON from a read-only transaction. HEAD applies the same administrator check and returns metadata without opening that transaction or recording a download. Campaign media reference reads share a single batch in PostgreSQL and Durable Objects. This keeps queries on the export transaction's single connection sequential. API session, profile, care and backup reads continue to enforce their account scope.
