# Frontend port status

The canonical product route is `/medication/`. The React and Dexie journal at `/journal/` is a separate device archive and incremental-sync client with its own interface and storage.

`apps/web/src/product` owns the product's TypeScript entry, startup, route coordination, writer-aware account transport, and React features. `apps/web/scripts/product.mjs` builds these modules and checks esbuild's input graph for replaced modules. The pnpm build owns its dependencies and invokes the shared compiler in `packages/web-build`. The build still reads shared HTML shells, CSS, translations, art, service-worker source and unported controllers from `web/`. `web/` also builds the incumbent app and supplies legacy server fixtures and historical public module URLs.

The bundle guard covers the replaced entry points and controllers. Static compatibility files are still emitted at their historical paths for installed clients, the design gallery, direct import tests, or approved recovery.

## Dependency boundaries

- **Build inputs.** The product and Journal resolve esbuild and Workbox from `apps/web`. The product uses `packages/web-build/compile.mjs` with templates and styles under `web/ui` and runtime assets under `web/public`. The Journal has its own Vite entry and still reads several image and font assets from `web/public`. The repository's combined Docker build still installs the npm package for its compatibility image.
- **Immediate browser dependencies.** `product.ts` still installs the original family panel, reminder delivery controller and account sync controller. `navigation.ts` retains the settings dialog coordinator and daily cycle controller. React owns the appointment and routine editors and cards, reports, calendar, backup, three preference forms, the cycle period and day editors and Today header. Shared helpers supply care indexing, focus, artwork and locale.
- **Indirect dependencies.** Unported controllers use the existing IndexedDB storage and schemas, care and scheduling rules, cryptography, and device recovery. Shared format and storage modules are still needed by the older client too. The typed account transport negotiates the PostgreSQL and compatibility APIs while retaining session and sync continuity.
- **Server runtime.** Node and Workerd tests against PostgreSQL exercise backend portability. Frontend independence remains open while `apps/web` consumes the original build inputs and controller modules.

## Current verification boundary

The production bundle input check rejects the replaced appointment, routine, backup, report, cycle period and Today story controllers. Browser route checks block those historical URLs when exercising the product screen matrix. The static files remain for the incumbent frontend and reference gallery. The isolated build omits the legacy npm installation and scripts while retaining `web/ui`, `web/public` and shared JavaScript. Full directory independence remains open.

Complete React ownership still requires the remaining settings and reminder presentation, the family panel and account-switch flow, the cycle dashboards, bulk entry, print and private archive workflows, and the sync panel. The primary HTML/CSS, translations, artwork, and service worker still come from shared source under `web/`. Removing that directory would also remove independent tools, historical formats, and the incumbent backend and browser fixtures. See [rebuild evidence](REBUILD_VERIFICATION.md) for this run's checks and [performance](PERFORMANCE.md) for measured results.

This verification uses synthetic data. The release status remains **NOT READY**.
