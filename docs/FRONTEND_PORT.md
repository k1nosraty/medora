# Frontend port status

The canonical product route is `/medication/`. The React and Dexie journal at `/journal/` is a separate device archive and incremental-sync client with its own interface and storage.

`apps/web/src/product` owns the TypeScript entry, startup, routing, writer-aware account transport and migrated React features. `apps/web/product-assets/ui` contains the remaining HTML shell and the shared CSS, icon and service-worker source. `apps/web/product-assets/public` contains fonts, translations, artwork, shared browser modules and the separately served tools. Both frontend builds use these sources and the compiler in `packages/web-build`. The incumbent npm build writes its own generated output into `web/public`.

The canonical esbuild guard rejects inputs from the root `web/` directory and the superseded controller list. Some public module URLs still serve installed clients, design-gallery interactions and historical recovery. Their names and public scopes remain stable.

## Dependency boundaries

- **Build inputs.** Both the primary product and Journal resolve their own frontend dependencies from the pnpm workspace. The Docker compatibility build consumes the same sources with a separate npm toolchain.
- **Active primary UI.** Account credentials, session identity, sync controls and conflicts, clinic-zone defaults, water reminder preferences, Cycle bulk entry and visit printing now have React owners. The original care sync algorithm lives in `features/sync/service.js` and both clients invoke it. Family management, device notification delivery and controls, remaining settings coordination, Today shell and parts of Cycle still use relocated JavaScript and HTML.
- **Shared services.** IndexedDB storage, backup formats, session transport, permission checks, date calculations, and reminder scheduling remain shared. Cycle bulk writes and visit printing also share `features/cycle/tools.js` with the compatibility application.
- **Server runtime.** The portable Node and Workerd APIs remain PostgreSQL-backed. The combined candidate Worker still integrates the native compatibility backend in `web/src`. The client build and browser fixture are independent of that server package.

The medication build excludes the old editor, view and appearance controllers by inspecting the bundler's input graph. Candidate HTML contains only the new medication screen hosts and empty dialog elements. The old phase, slot and snooze preference templates are absent. The earlier source files and unbundled URLs remain for the incumbent and design gallery. A standalone fixture build omitted all three controllers and seven medicine screen/form templates. Disabling the independent gallery output in both probe copies yielded byte-identical primary HTML, bundles and service worker with and without those ten files. Shared helpers retained include quantity and recurrence rules, the care index, timezone and locale, artwork, IndexedDB, backup readers, reminder scheduling, family access, and account sync. The React calendar agenda places the React article and disposes its root. Today now receives a React-managed featured-dose layout without relocating its children.

## Remaining compatibility tree

| Path | Current use |
| --- | --- |
| `web/src`, `web/wrangler.jsonc` | Native compatibility API, archive and operation recovery, alarm implementations and runtime configuration. Selected server modules also support the portable API. |
| `web/scripts`, `web/test` | Incumbent build, synthetic fixtures, historical format readers, verification, and backup or rollback tools. |
| `web/public` | Ignored output recreated by the compatibility build. The primary app has no build or browser dependency on this generated output. |
| `web/package.json`, lockfile, JS and Playwright configs | Compatibility tools and test configuration. Native Workerd browser tests live in `tests/product`. |
| `apps/web/product-assets` | Canonical assets and shared layout, native controllers still required by the product, incumbent or gallery, plus compatibility modules at stable public URLs. |

The source move retires the tracked `web/ui` and `web/public` copies. Whole-tree deletion would remove the native backend, historical archive tools and compatibility fixtures.

## Current verification boundary

`node scripts/verification/frontend-independence.mjs` installs dependencies from the workspace lockfile in a temporary copy without the root `web/` tree, builds the primary frontend and runs its standalone browser suite against the production output with a synthetic API. Use `--offline` with a populated pnpm cache. The screen matrix aborts and records requests for the replaced controller URLs and any `/web/` path. Full Workerd-backed product and handoff tests use separate local fixtures.

The React migration stays **INCOMPLETE** while family management, device notification controls, the settings shell, Today coordination, and the remaining Cycle views use legacy UI modules and templates. See [rebuild verification](REBUILD_VERIFICATION.md) and [performance](PERFORMANCE.md) for test outcomes and the current visual and release gates. Release status remains **NOT READY**.
