## Activity artwork palettes

Routine and appointment artwork share their canvases, alpha data and color profiles across ten tints. The optical-glass WebP in `product-assets/public/design/optical-glass` supplies those chunks. The corresponding `.vp8` file in `product-assets/artwork-palettes` contains the ten color chunks in the order specified by `packages/web-build/artwork-palettes.mjs`. Both builds reconstruct the public WebP variants at their established URLs. The matte artwork and service-worker cache routing retain their existing behavior.

This representation removes about 4.6 MB of repeated source bytes. It deliberately retains the existing color compositions. CSS hue rotation and a fitted tint changed colors in visible parts of the sampled glass assets. Adding a design-approved variant requires exporting it with the same canvas, alpha and profile as its base. Use `node apps/web/scripts/pack-artwork.mjs <optical-glass-source> <palette-output>` on a source tree with all ten complete `colors/` directories. The tool requires a byte-identical round trip before writing each palette. Update the tested asset digest only after reviewing intended artwork changes.

The final review counted 940 distinct public files totaling 11,166,318 bytes. The 94 tracked palettes total 6,561,858 bytes, excluding their existing base images. Five local emissions took 24–65 ms with a 36 ms median. The variants count toward the static deployment payload. They stay out of the startup precache and enter the versioned artwork cache on demand. The sampled startup issued zero color-variant requests. No byte-identical duplicate public variant had a removable URL.

Twelve sampled Routine and Visit colors retained the base alpha exactly. A best-fit affine RGB tint still differed by up to 8.90 levels on average and by up to 32.06 levels at the 95th percentile within pixels of at least 50 percent opacity. A single mask would also discard the palette-specific color composition. Keep the established output and cache URLs for these assets. Matte artwork continues to use its existing shared icon per shape.
